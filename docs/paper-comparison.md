# Foundational Literature Comparison: Browser vs. Website Fingerprinting

This document synthesizes three foundational research papers that define the modern fingerprinting threat landscape across the application and network layers.

| Research Dimension                   | Paper 1: _Eadem, Sed Aliter_ (IMC '26)                                                                         | Paper 2: _Explainable & Adversarially Resilient DL_ (IJCSIS '26)                                            | Paper 3: _Website Fingerprinting Survey_ (ACM CSUR)                                               |
| :----------------------------------- | :------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------ |
| **Primary Objective**                | Measure real-world longitudinal instability ("FP-flips") of browser fingerprints over time.                    | Propose a deep learning framework for user identification that resists adversarial spoofing[cite: 16].      | Systematically survey network-level Website Fingerprinting (WF) attacks and traffic defenses.     |
| **Privacy vs. Security Perspective** | **Privacy:** Treats fingerprinting as a covert tracking mechanism subject to natural systemic drift[cite: 16]. | **Security:** Treats fingerprinting as a defensive authentication and fraud-detection mechanism[cite: 16].  | **Privacy:** Treats encrypted traffic metadata as a side-channel threat to user anonymity.        |
| **Observation Layer**                | Application Layer (JavaScript DOM & Web APIs)                                                                  | Application Layer (Client Telemetry & System Configurations)                                                | Transport / Network Layer (Encrypted Traffic Packets)                                             |
| **Identification Target**            | The client device / browser environment across multiple sessions.                                              | An unauthorized user, attacker, or fraudulent bot.                                                          | The specific destination URL / web page being visited.                                            |
| **Threat Model & Adversary**         | Third-party web tracker or advertising script.                                                                 | Evasive attacker manipulating attributes to bypass security[cite: 16].                                      | Passive local network eavesdropper (ISP, Rogue Wi-Fi).                                            |
| **Data Source & Scale**              | Large-scale longitudinal real-world browser telemetry dataset.                                                 | Conceptual / Literature synthesis (assumes multi-source telemetry).                                         | Survey of closed-world and open-world encrypted traffic datasets (e.g., Tor cells).               |
| **Role of Perturbation**             | Natural system drift (OS updates, browser patches, display changes).                                           | Deliberate adversarial evasion (spoofing attributes)[cite: 16].                                             | Active defense mechanism (dummy traffic padding, morphing).                                       |
| **Encrypted Tunnel Impact**          | Ineffective: VPNs/Tor do not hide internal Web APIs from JavaScript.                                           | Ineffective: VPNs/Tor do not alter local execution environments.                                            | Active target: The attack operates _on_ the VPN/Tor encrypted tunnel.                             |
| **Methodology**                      | Longitudinal statistical measurement and ablation of feature changes.                                          | Conceptual 5-layer architecture combining representation learning, adversarial training, and XAI[cite: 16]. | Taxonomy of Traditional ML (k-NN, CUMUL) and Deep Learning (CNN, Var-CNN) classifiers.            |
| **Evaluation Metrics**               | Feature stability rate, turnover interval, similarity decay.                                                   | Identification accuracy, adversarial robustness, and explainability[cite: 16].                              | True Positive Rate (TPR), False Positive Rate (FPR), bandwidth and latency overhead.              |
| **Key Limitation**                   | Observational drift study; does not actively benchmark anti-fingerprinting defenses.                           | Purely conceptual framework; lacks empirical code validation.                                               | High false positives in realistic open-world settings; heavy bandwidth costs for traffic padding. |
