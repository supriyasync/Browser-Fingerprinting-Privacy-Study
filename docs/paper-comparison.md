# Foundational Literature Comparison: Browser vs. Website Fingerprinting

This document synthesizes three foundational research papers that define the modern fingerprinting threat landscape across the application and network layers.

| Research Dimension           | Paper 1: _Eadem, Sed Aliter_ (IMC '26)                                | Paper 2: _Explainable & Adversarially Resilient DL_ (IJCSIS '26)                                | Paper 3: _Website Fingerprinting Survey_ (ACM CSUR)                                       |
| :--------------------------- | :-------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------- |
| **Primary Objective**        | Measure real-world longitudinal instability ("FP-flips") over time.   | Propose a deep learning framework for user identification that resists adversarial spoofing.    | Systematically survey network-level Website Fingerprinting (WF) attacks and defenses.     |
| **Privacy vs. Security**     | **Privacy:** Treats fingerprinting as a covert tracking mechanism.    | **Security:** Treats fingerprinting as a defensive authentication mechanism.                    | **Privacy:** Treats encrypted traffic metadata as a side-channel threat to anonymity.     |
| **Observation Layer**        | Application Layer (JavaScript DOM & Web APIs)                         | Application Layer (Client Telemetry & System Configurations)                                    | Transport / Network Layer (Encrypted Traffic Packets)                                     |
| **Identification Target**    | The client device / browser environment across multiple sessions.     | An unauthorized user, attacker, or fraudulent bot.                                              | The specific destination URL / web page being visited.                                    |
| **Threat Model & Adversary** | Third-party web tracker or advertising script.                        | Evasive attacker manipulating attributes to bypass security.                                    | Passive local network eavesdropper (ISP, Rogue Wi-Fi).                                    |
| **Data Source & Scale**      | Large-scale longitudinal real-world browser telemetry dataset.        | Conceptual / Literature synthesis (assumes multi-source telemetry).                             | Survey of closed-world and open-world encrypted traffic datasets (e.g., Tor cells).       |
| **Role of Perturbation**     | Natural system drift (OS updates, browser patches, display changes).  | Deliberate adversarial evasion (spoofing attributes).                                           | Active defense mechanism (dummy traffic padding, morphing).                               |
| **Encrypted Tunnel Impact**  | Ineffective: VPNs/Tor do not hide internal Web APIs from JavaScript.  | Ineffective: VPNs/Tor do not alter local execution environments.                                | Active target: The attack operates _on_ the VPN/Tor encrypted tunnel.                     |
| **Methodology**              | Longitudinal statistical measurement and ablation of feature changes. | Conceptual 5-layer architecture combining representation learning, adversarial training, & XAI. | Taxonomy of Traditional ML (k-NN, CUMUL) and Deep Learning (CNN, Var-CNN) classifiers.    |
| **Evaluation Metrics**       | Feature stability rate, turnover interval, similarity decay.          | Identification accuracy, adversarial robustness, and explainability.                            | True Positive Rate (TPR), False Positive Rate (FPR), bandwidth and latency overhead.      |
| **Key Limitation**           | Observational drift study; does not benchmark active defenses.        | Purely conceptual framework; lacks empirical code validation.                                   | High false positives in realistic open-world settings; heavy bandwidth costs for padding. |
